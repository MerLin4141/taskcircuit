# TaskCircuit v0.1.1

## English

### Highlights

This release improves CLI readability, agent failure reporting, retry decisions, and Windows background startup. TaskCircuit remains a trusted-local runtime.

### CLI improvements

`status`, `work <id>`, `inbox`, `runtime status`, and `doctor` display human-readable output by default and support `--json` for automation. Full Work Item and Interaction IDs remain available; external Agent Session IDs remain redacted.

### Agent error handling

Error codes include `quota_exceeded`, `rate_limited`, `auth_failed`, `agent_unavailable`, `agent_timeout`, `agent_protocol`, and `agent_execution`. Existing `agent_resume`, `agent_environment`, and `agent_reported_failure` remain supported. Classification is best-effort and depends on CLI process output; raw stderr is not returned as a normalized error.

Quota, authentication, unavailable CLI, and protocol failures do not automatically retry. Rate limits and timeouts can retry under the configured policy. `agent_execution` is retryable only when a temporary failure is recognized or explicitly marked retryable; attempts remain bounded by the existing policy.

### Windows runtime

Windows Task Scheduler starts a GUI-subsystem bootstrap that launches PowerShell without creating a console window; PowerShell also receives `-WindowStyle Hidden`. Hub and Worker already use `windowsHide`. The bootstrap waits for the existing Job Object launcher and preserves process containment; `runtime run` remains the foreground command. Existing installations must run `taskcircuit runtime install` again to update the Scheduled Task Action.

### Compatibility

The SQLite schema is unchanged and no database migration is required. Existing `agent_execution` records remain readable; v0.1.0 user data does not need to be deleted.

### Upgrade

From an existing source checkout, on Windows, stop the runtime first if it is running, then update and rebuild:

```powershell
taskcircuit runtime stop
git pull
npm ci
npm run build
npm link
taskcircuit runtime install
taskcircuit runtime start
taskcircuit --version
taskcircuit runtime status
```

`runtime install` updates the Windows Scheduled Task Action and preserves user data. Skip the stop command if the runtime is already stopped. This is a source checkout upgrade, not an npm package release; the package remains private.

### Verification

Run format, typecheck, tests, audit, and the isolated Windows Mock regression. See the [release checklist](../release-checklist.md) and the commit's GitHub Actions results for recorded outcomes. An actual Windows reboot/logon cycle was not performed during validation. Real-agent E2E is not required for this release preparation.

## 中文

### 主要更新

本版改善 CLI 可读性、Agent 失败提示和重试判断，以及 Windows 后台启动体验；TaskCircuit 仍使用本地可信执行边界。

### CLI 改进

`status`、`work <id>`、`inbox`、`runtime status` 和 `doctor` 默认显示人类可读内容，并支持 `--json` 自动化输出。Work Item 和 Interaction ID 保持完整，外部 Agent Session ID 继续隐藏。

### Agent 错误处理

错误类型包括 `quota_exceeded`、`rate_limited`、`auth_failed`、`agent_unavailable`、`agent_timeout`、`agent_protocol` 和 `agent_execution`；既有 `agent_resume`、`agent_environment`、`agent_reported_failure` 继续保留。错误分类依赖 CLI 进程输出，属于尽力判断；归一化错误不返回原始 stderr。

额度耗尽、认证失败、CLI 不可用和协议错误不会自动重试；限流和超时可按配置策略重试。`agent_execution` 仅在识别为临时故障或明确标记可重试时重试，次数仍受现有策略约束。

### Windows 后台运行

Windows 计划任务先启动无控制台的图形子系统启动器，再以不创建控制台的方式启动 PowerShell；PowerShell 同时带有 `-WindowStyle Hidden`。Hub 和 Worker 原本已有 `windowsHide`。启动器等待现有 Job Object 管理的运行时并保留进程清理机制；`runtime run` 仍是前台命令。已有安装需要重新执行 `taskcircuit runtime install` 更新计划任务。

### 兼容性

SQLite schema 未变化，无需数据库迁移。旧 `agent_execution` 记录仍可读取，不需要删除 v0.1.0 用户数据。

### 升级

在已有源码目录中，Windows 用户先停止正在运行的 Runtime，再执行：

```powershell
taskcircuit runtime stop
git pull
npm ci
npm run build
npm link
taskcircuit runtime install
taskcircuit runtime start
taskcircuit --version
taskcircuit runtime status
```

`runtime install` 用于更新 Windows Scheduled Task Action，用户数据会保留；如果 Runtime 已停止，可跳过 stop。这是源码升级，项目包仍为 private，并未发布到 npm。

### 验证

运行格式检查、类型检查、测试、审计和隔离 Windows Mock 回归；具体结果见[发布检查表](../release-checklist.md)和对应提交的 GitHub Actions。验证期间没有执行实际 Windows 重启和登录周期；本轮发布准备不要求真实 Agent E2E。
