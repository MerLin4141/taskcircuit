# TaskCircuit v0.4.0

## English

TaskCircuit v0.4 connects GitHub Issues and signed webhooks to durable Codex and Claude Code Automations. An Agent can continue in the same session, ask for a local answer, or resume later. Notifications can go to the local console or a Feishu group.

- Active Sources use Source API 2. Generic Webhook and GitHub validate signatures on the raw request, persist delivery identity, and use a dedicated loopback listener. GitHub accepts allowlisted Issue openings and Issue comments. PR conversation comments do not trigger Issue Automations.
- Feishu uses Channel API 2 for outbound signed text through group custom bots. Operators answer NeedsInput through the local Inbox and Answer commands.
- GitHub Issue Fixer and Webhook Task Runner are copyable declarative templates. The same CLI previews and applies them.
- Hub, Worker, Doctor and Windows Runtime share config selection. Windows install pins the chosen config. Doctor checks configuration and required environment references while the Hub is offline.
- Database Schema 10, Declarative Schema 1, Source API 1/2, Agent API 1 and Channel API 1/2 are supported. Existing v0.3 local configuration and Automations remain usable.

Trusted Local plugins execute with local user permissions. Capability metadata does not provide OS-level isolation. Durable intake deduplicates deliveries. An external side effect, including Feishu delivery after a lost response, can still occur more than once. For public intake, an operator-managed HTTPS proxy or tunnel forwards the selected integration path to loopback and keeps the management API private.

GitHub Source is inbound only, with no write-back. Feishu sends outbound notifications, with no in-chat answers. Multi-agent runtime, remote Workers, cloud runtime and multi-user/RBAC remain outside this version.

RC validation covered real Codex Ask/Answer/Resume and real Claude Continue using isolated workspaces. Real public GitHub delivery, real Feishu receipt and the combined flagship flow await operator prerequisites. Isolated Windows scheduled-task installation, start, restart, stop and removal were validated. An actual Windows reboot/logon was not tested.

## 简体中文

TaskCircuit v0.4 可用 GitHub Issue 和签名 Webhook 触发 Codex 或 Claude Code 自动化，保留同一会话继续执行，支持本地回答和稍后恢复。通知可投递到本地控制台或飞书群。

- Source API 2 支持主动来源。Generic Webhook 和 GitHub 对原始请求体验签，在独立的回环监听端口持久化投递标识。GitHub 只接收允许列表内的 Issue 新建和 Issue 评论，PR 会话评论不会触发 Issue 自动化。
- 飞书通过 Channel API 2 向群自定义机器人发送签名纯文本。需要回答时，操作者使用本地 Inbox 和 Answer 命令。
- GitHub Issue Fixer 和 Webhook Task Runner 提供可复制、编辑、预演和应用的声明式模板。
- Hub、Worker、Doctor 和 Windows Runtime 使用统一的配置选择。Windows 安装时固定配置路径，Doctor 可在 Hub 离线时检查配置和所需环境引用。
- 支持数据库 Schema 10、声明式 Schema 1、Source API 1/2、Agent API 1、Channel API 1/2。现有 v0.3 本地配置和自动化可继续使用。

Trusted Local 插件以本机用户权限运行，能力元数据不提供操作系统级隔离。持久化接入可以对同一投递去重，外部操作仍可能重复。例如飞书已接收、成功响应丢失时，重试可能再次发送。公网接入需由操作者管理 HTTPS 代理或隧道，仅将指定集成路径转发到回环端口，管理 API 保持本地。

GitHub 仅接收事件，无回写。飞书仅发送通知，无群内回答。多 Agent、远程 Worker、云运行时和多用户/RBAC 不在本版范围内。

RC 在隔离目录验证了真实 Codex 的提问、回答与恢复，以及真实 Claude 的 Continue。公网 GitHub、真实飞书收件和完整旗舰链路仍缺操作者前置条件。已验证隔离 Windows 计划任务的安装、启动、重启、停止和移除。实际 Windows 重启或重新登录未测试。
