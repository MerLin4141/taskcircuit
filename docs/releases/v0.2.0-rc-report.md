After transfer, the target checkout also passed 46 files and 410 tests with 0 failed and 0 skipped, plus format check, typecheck, standalone build and npm audit (0 vulnerabilities). The isolated fresh-install/Mock and v0.1.2 upgrade smoke tests were repeated after that final regression.

Phase 6 real E2E evidence remains in [the Phase 6 report](../design/v0.2-phase6-real-agent-e2e-report.md): Codex CLI 0.167.0 and Claude Code 2.1.319 each completed a real autonomous loop, resume, NeedsInput/Answer, Later and cancellation. ## Hygiene and staging

The local scan found no real secret values; two credential-shaped values in an Event validation test are deliberate fictional strings. No runtime database, sidecar, log, PID, `.env` or smoke home was included in the candidate inventory. [Staging preview](v0.2.0-staging-preview.md) lists intended paths and explicitly excludes the local-only comparison document. Nothing was staged.

## Known limits

Actual Windows reboot/logon and Linux process-group cleanup were not tested. The isolated Windows recovery test used a controlled polling delay. Cancellation did not include a complete independent descendant inventory. Real deadline, response-loss, Worker crash and Hub crash were not independently injected against both real CLIs. Watch is not a complete Root timeline; Automation creation requires trusted configuration. Trusted Local is not an authentication boundary or OS sandbox, and external side effects are not exactly-once.

## Windows CI scale-test stabilization

The original Windows CI run [42639973181](https://github.com/MerLin4141/taskcircuit/actions/runs/42639973181) failed on test timeouts. Commit `1b37dbea1c0612d937a337bedd947777b66527d9` first scoped `synchronous=OFF` to the scale and pagination seed tests. Its [CI run 42735607809](https://github.com/MerLin4141/taskcircuit/actions/runs/42735607809) passed: Windows 410/410, Ubuntu 405 passed and 5 expected Windows-only skips. The Windows 10,000-Event test took 69.254 seconds of its 120-second timeout, prompting a stability investigation rather than a performance SLA.

The follow-up also sets `journal_mode=MEMORY` only on those test connections, retains the existing data sizes and assertions, and gives pagination 15 seconds for CI scheduling margin. Production SQLite settings and the durability and recovery tests are unchanged. On one local Windows targeted run, 1,000 and 10,000 Events took 0.283 and 2.668 seconds respectively (9.43x for 10x input), 1,000 Decisions took 1.435 seconds, and pagination took 0.105 seconds. Two measurements do not establish asymptotic complexity or a product performance guarantee.

The subsequent GitHub CI runs and their Windows repeatability results must be checked on the final candidate commit before removing the release blocker.
