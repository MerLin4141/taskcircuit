# TaskCircuit v0.2.0

## Overview

TaskCircuit is a durable autonomous loop runtime for CLI agents. Events route to Automations and Roots; Agents can continue, ask, wait until later, complete, fail or stop. Definition versions and decisions are immutable, and local policy checks precede execution.

## Autonomous loops and limits

One Root can span multiple Executions and continue the same Agent Session. Continue proposes another run; admission rechecks Root state, authorization, active execution, max runs and deadline. Defaults are 8 runs and 2 hours. Feedback cannot alter the frozen limits, Agent, workspace or capabilities.

## Reliability and UX

Lease fencing rejects stale writes. Unknown execution outcomes do not automatically replay; result receipts and bounded reconciliation help confirm Hub commits after a lost response. Ask/Answer, Retry, Later, scheduling, notifications and Windows Runtime remain available. Automation, Event and Root commands, a Mock loop, human-readable watch output and Doctor checks are included. Trusted Agent, event and workspace configuration must exist before Automation creation. Watch does not show every Event/Root/Continue transition.

## Agent compatibility

These are verified versions, not the only supported versions: Codex CLI **0.167.0** and Claude Code **2.1.319**.

| Capability          | Codex                 | Claude Code |
| ------------------- | --------------------- | ----------- |
| Initial execution   | Passed                | Passed      |
| Continue loop       | Passed                | Passed      |
| Session resume      | Passed                | Passed      |
| NeedsInput / Answer | Passed                | Passed      |
| Later               | Passed                | Passed      |
| Cancellation        | Passed*               | Passed*     |
| Real `max_runs`     | Not separately tested | Passed      |

\* Cancellation requested termination of the managed process, and its ProcessRunner received an AbortSignal; a complete descendant-process inventory was not independently verified. Execution conservatively became `execution_outcome_unknown`. A process stop cannot retract an external request.

Deadline, response loss, Worker crash and Hub crash are covered by automated/fake-agent reliability tests, not independently injected against both real CLIs. The automated suite does not include every real-agent experiment. Real provider use may consume quota.

## Upgrade from v0.1.2

The v0.1.2 Generation 1 schema 4 to v0.2 Generation 2 schema 10 storage upgrade is **one way**. Stop the old runtime, resolve active or uncertain work, and independently back up the entire TaskCircuit home before upgrading. During cutover TaskCircuit creates `taskcircuit-v1-backup-<id>.sqlite` in the same home before quarantining `taskcircuit.db`; current state lives in `taskcircuit-gen2.db`. Backup or safety-check failures block migration. Direct downgrade is unsupported; restore a pre-upgrade backup, which does not include work done under v0.2. See the [upgrade guide](../upgrade-v0.2.md).

Legacy CLI and API endpoints remain; Automation, Event and Root interfaces are additive. Watch adds human-readable labels while retaining change types. The one-way store transition and schema change are compatibility boundaries; do not assume older binaries can use the new store. `TASKCIRCUIT_HOME` and `TASKCIRCUIT_PORT` remain supported. v0.2 keeps package metadata private and is not published to npm.

## Known limitations

- Trusted Local only; loopback is not authentication and capability metadata is not an OS security sandbox.
- External side effects are not exactly-once; local termination cannot retract remote requests and escaped descendants may survive.
- Windows is the primary validated platform. Isolated start/stop/restart and pending-continuation recovery were tested with controlled timing; actual Windows reboot/logon was not tested. Linux process-group cleanup was not verified.
- No Approval, ActionIntent, Outbox, plugin architecture, GitHub Source plugin, Slack/email channels, multi-user/RBAC, remote Worker, cloud runtime, OS sandbox, or complex token/cost budget.
