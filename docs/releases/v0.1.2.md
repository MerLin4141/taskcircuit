# TaskCircuit v0.1.2

## Overview

This reliability update improves uncertain execution handling, cancellation, result confirmation, scheduler behavior, and Agent compatibility diagnostics.

## Execution reliability

Lease expiry does not blindly replay Agent work whose outcome is unknown. Such work is marked `execution_outcome_unknown` for operator review. A failure proven to occur before Agent startup can still follow the configured retry policy; uncertain outcomes cannot. Lease fencing continues to reject stale Worker writes.

## Cancellation

Worker cancellation and lease loss propagate through Agent adapters to ProcessRunner. Windows process-tree handling has been tested with isolated processes. Stopping a process cannot retract an external request already sent.

## Result confirmation and heartbeat

A result submission uses a stable submission ID and canonical SHA-256 digest. Hub stores a durable receipt with its state changes: the first submission is `accepted`, an identical replay is `already_committed`, and conflicting submissions are rejected. After a lost response, a Worker can query the receipt and use bounded reconciliation instead of running the Agent again. Receipts confirm a Hub state commit, not exactly-once external side effects. Clients without a submission ID retain the previous API behavior.

A temporary heartbeat failure is distinct from explicit 409 ownership loss; recovery may restore a healthy state. A conservative deadline requests Agent shutdown when ownership cannot be confirmed.

## Scheduler

A scheduler tick uses one wall-clock snapshot for due checks and Cron advancement, preventing an intra-tick clock rollback from reusing a firing time. Existing duplicate firing records are preserved; the affected schedule is isolated for the current tick with a diagnostic, allowing other schedules to proceed. This is not persistent quarantine: later ticks may report the same condition again.

## Platform and database

Windows is the primary validated platform. Isolated runtime, scheduler, fake-process and real-Agent tests were run; an actual Windows reboot or logoff/login cycle was **NOT TESTED**. Linux process-group cleanup is **NOT TESTED**; Linux CI exercises other cross-platform behavior and does not establish process-group reliability.

Migration required: **NO**. The SQLite schema version is unchanged; tested v0.1.1 databases remain readable. A historical retry without proof of safe execution is conservatively treated as an unknown outcome.

## Security model and limitations

TaskCircuit uses a Trusted Local execution model. Job Objects and process-tree management control process lifetimes; they are not an OS security sandbox and do not provide filesystem, network, or credential isolation.

- External side effects are not exactly-once, and terminating an Agent cannot retract requests already sent.
- Detached or escaped descendants may survive process cleanup.
- Linux process-group cleanup and Windows reboot/logon recovery were not validated.
- Real Agent compatibility applies only to the CLI versions and scenarios listed above; Later and real response-loss reconciliation were not tested.
- Abnormal Schedule isolation is per tick, not persistent quarantine.
