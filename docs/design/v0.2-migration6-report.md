# TaskCircuit v0.2 — Migration 6

Migration 5 is the Generation 1 to Generation 2 storage cutover. Migration 6 runs only on a Generation 2 database with schema 5. Startup does not start serving the Hub until it commits. A SQLite `BEGIN IMMEDIATE` transaction creates the domain tables, backfills each existing Work Item with a distinct `legacy:<work-item-id>` Root, rebuilds `work_items` with `root_id NOT NULL` and an FK, checks foreign keys and existing session ownership, then records schema 6. Foreign keys are temporarily disabled outside the rebuild transaction and restored afterwards. A future schema greater than 6 is rejected as `database_schema_too_new`.

| Existing Work Item                                                       | Legacy Root       | Reason                                                                                      |
| ------------------------------------------------------------------------ | ----------------- | ------------------------------------------------------------------------------------------- |
| active                                                                   | active            | Work remains eligible; running or claimed execution overrides this to blocked.              |
| waiting_input, waiting_schedule                                          | waiting           | Existing human interaction or schedule remains resumable.                                   |
| completed                                                                | completed         | Preserve the historical completion.                                                         |
| failed                                                                   | failed            | Preserve failure; do not invent success.                                                    |
| cancelled                                                                | cancelled         | Preserve cancellation.                                                                      |
| any with running / claimed / `execution_outcome_unknown`                 | blocked           | External outcome may need verification.                                                     |
| multiple old Work Items sharing the same adapter and external session ID | blocked           | Preserve both session records but do not resume an ambiguous external session across Roots. |
| unrecognized state                                                       | migration refused | No historical state is invented.                                                            |

Legacy roots use the original Work Item timestamps. Historical terminal time is copied only where a reliable completed timestamp exists; historical budget, costs, tokens and depth remain unknown. Existing IDs, sessions, interactions, schedules, firings, notifications, runtime changes and result receipt metadata are preserved. Root ownership is immutable, definition versions are immutable, known subject scope/key pairs are unique within a Root, and the session binding is checked against the owning Work Item. Duplicate historical external session identifiers remain readable but block the affected Roots; new cross-Work-Item reuse is rejected.

The migration is one transaction. Tests kill an isolated migration process after definition creation, root table creation, during legacy population, before Work Item constraint finalization and before recording version 6; restart sees schema 5 and retries. Two coordinated processes also test serialization. The 100 and 1,000 Work Item tests are sanity checks, not a production-scale benchmark. The v0.1.2 → Generation 2 → schema 6 test uses the actual archived v0.1.2 runtime and a temporary database; Migration 6 is checked not to change the quarantined legacy database.

A schema 6 store is not a supported rollback to v0.1.2: restore a pre-cutover backup only with awareness that later changes will be lost. The guard, backups and legacy quarantine do not isolate a malicious same-user process. No real Agent or formal user database was used.
