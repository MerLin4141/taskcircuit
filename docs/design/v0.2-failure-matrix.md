## Outbox 协议及上线边界

在同一 DB 事务中写 Decision + ActionIntent + Outbox，commit 前不调用外部服务；dispatcher 使用 `(outbox_id,epoch,lease)` claim 并在 send 前持久化 `sending`。pending 且有证明尚未发送可以恢复，`sending` 失联一律 unknown。已验证对方幂等协议且 key/请求摘要不变，或权威查询在一致性窗口后证明未执行，才可按策略重试；否则冻结、人工核实。过期 epoch 不能写 receipt，已接受的完全相同 receipt 可幂等确认。记录和补偿不是 exactly-once；通知投递策略单独定义。v0.2 默认不开放通用真实 Action/outbox，外部来源认证、权限、OS 隔离缺失时不开放不可信自动化。
