# TaskCircuit v0.1.2 开发前代码审计

> 审计基线：v0.1.1，HEAD `4fb7cf13fd7c243c8d2bd82ece34f75ae37a55df`。结论分为 **源码事实**、**隔离测试观察** 和 **风险推断 / 待验证**；本轮不修改代码或数据库，不调用真实 Agent 或外部平台。

## 结论和优先级

| 编号 | 优先级 | 结论与证据                                                                                                                                                                                                                                                                                                  | 证据等级                                                             |
| ---- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| A1   | P0     | 租约过期后 [Hub](../../src/hub.ts#L933) 可将同一 running Execution 交给新 Worker；[Worker](../../src/worker.ts#L64) 检测心跳失败仅置标志，直到 Agent 返回才拒绝提交，不中止 Agent。两个进程的实际工作可能重叠，外部写入可能重复；现有 token 只能阻止旧结果入库。                                            | 静态事实；重叠与副作用重复是可由故障触发的风险，本轮未执行该故障复现 |
| A2   | P0     | 首次执行的 session 仅在适配器返回并提交结果时写入 [agent_sessions](../../src/hub.ts#L1071)；Agent 已启动甚至完成外部动作后 Worker 崩溃，Hub 没有本轮 session，过期重领会以新会话再次执行。                                                                                                                  | 静态事实及故障风险；不推断每个 Agent 均可在进程中途提供可持久化 ID   |
| A3   | P0     | [AgentTimeoutError](../../src/agents/errors.ts#L45) 被标为可重试，[Hub](../../src/hub.ts#L1181) 在策略允许时安排重试；超时不证明外部副作用未发生。取消只更新数据库，[Worker](../../src/worker.ts#L110) 不接收取消信号、[ProcessRunner](../../src/agents/process.ts#L64) 的 AbortSignal 未由实际适配器传入。 | 静态事实；副作用是否发生取决于具体 Agent 和外部系统                  |
| A4   | P1     | 任意一次心跳失败永久设置 `heartbeatFailed`；即使后续续租恢复成功，Agent 的有效结果也会被丢弃，直至租约过期重领。没有按失败类型和当前有效所有权核实。                                                                                                                                                        | 源码事实，故障注入待验证                                             |
| A5   | P1     | 结果提交后 token 清除，重复提交返回 409；Worker 的结果请求只有一次且无结果持久化/读回。如果 Hub 已提交但 HTTP 回应丢失，Worker 无法区分已保存和未保存。                                                                                                                                                     | 源码事实，网络中断复现待验证                                         |
| A6   | P1     | [ProcessRunner](../../src/agents/process.ts#L64) 使用 `child.kill()` 终止直接子进程，不证明 descendants 全部退出；常驻 worker 的 stop 标志不取消当前 `workOnce`。Windows Runtime 的 Job Object 与单次 Agent 超时是不同层级。                                                                                | 源码事实，实际子进程树残留待隔离测试                                 |
| A7   | P2     | CLI 能力探测只检查 help 关键字；对 CLI 版本、输出事件结构和 resume 语义变化没有完整兼容性保证。                                                                                                                                                                                                             | 源码及假 CLI 测试；真实版本待验证                                    |

P0 在本审计中表示“在允许 Agent 对外执行有副作用操作的现有模式下，建议作为 v0.1.2 发布前的安全恢复门槛”，不是声称已经发生真实事故或已实现通用去重。A1–A3 指向同一不确定执行问题，可作为一组修复；即便立即停止本地进程，也无法撤销已经发出的请求。

## 当前架构与文件

CLI [src/cli.ts](../../src/cli.ts#L53) 启动 Hub/Worker；[src/hub.ts](../../src/hub.ts#L47) 持有 SQLite、API、租约、调度和通知事务；[src/worker.ts](../../src/worker.ts#L40) 通过 HTTP 领取、调用 Agent 和提交；[src/adapter.ts](../../src/adapter.ts) 定义单个 `execute` 接口；[src/agents/](../../src/agents/) 实现 Mock 以外的 Codex/Claude 协议、进程和错误分类；[src/scheduling.ts](../../src/scheduling.ts) 定义 Cron/退避算法；[src/migration.ts](../../src/migration.ts) 保存 schema 及版本；[src/config.ts](../../src/config.ts#L84) 固定路由和 adapter 配置；[src/platform/windows/](../../src/platform/windows/) 与 [scripts/windows/](../../scripts/windows/) 管理 Windows 启动和进程。

## 实际状态与迁移

权威类型见 [src/domain.ts](../../src/domain.ts#L1)，不要与目标设计中的状态混用。

| 对象        | 实际迁移入口与结果                                                                                                                                                                                                                                                                                                   |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Work Item   | 事件创建 `active`；Ask → `waiting_input`；回答 → `active`；Later 或可重试失败 → `waiting_schedule`；到期执行 → `active`；成功/最终失败 → `completed/failed`；取消 → `cancelled`。见 [hub.ts](../../src/hub.ts#L643)、[hub.ts](../../src/hub.ts#L881)、[hub.ts](../../src/hub.ts#L1104)。                             |
| Execution   | 新建 `queued`；领取直接写 `running`，租约到期的 `running` 也可重新领取；Ask → `waiting_input`；Later → `completed` 并建一次性计划；失败 → `failed`，满足条件时另建重试计划；成功 → `completed`；取消将 queued/running/claimed/retry_wait 改为 cancelled。类型含 claimed/retry_wait，但主要领取路径直接使用 running。 |
| Interaction | 结果提交创建 `open`；回答事务内改 `resolved` 并建下一执行；工作项取消时 `open → cancelled`。没有审批主体、有效期和 approved/rejected 状态。                                                                                                                                                                          |
| Event       | 来源/type 匹配一条 route，创建新 event、Work Item、Execution；无 delivery ID 状态机及通用来源幂等。每次重复发事件都会新建工作。见 [hub.ts](../../src/hub.ts#L789)。                                                                                                                                                  |

一次有效结果在同一个 `BEGIN IMMEDIATE` 事务里更新 session、Execution、Work Item、Interaction 或 schedule，因此正常提交路径不存在由“中途单条 SQL 成功”直接造成的部分提交；并不能由此证明所有异常状态不存在。回答与调度构造新 Execution 时沿用父执行的 session 引用；[tests/runtime.test.ts](../../tests/runtime.test.ts#L99)、[tests/scheduling.test.ts](../../tests/scheduling.test.ts#L46) 和 [tests/scheduling.test.ts](../../tests/scheduling.test.ts#L255) 覆盖了模拟的会话续用。

## Lease、恢复与竞争

[hub.ts](../../src/hub.ts#L55) 使用 WAL、`foreign_keys=ON`、`busy_timeout=5000`；`tx` 使用 `BEGIN IMMEDIATE`。同一数据库的领取在写事务中查询并更新，生成随机 token，30 秒到期；Worker 每 10 秒尝试心跳（[worker.ts](../../src/worker.ts#L64)）。[valid](../../src/hub.ts#L990) 要求 ID、workerId、token、running 状态和未过期时间一致，故过期或被重领的旧 Worker 不能正常提交结果。[tests/runtime.test.ts](../../tests/runtime.test.ts#L67) 验证单 Hub 竞争、续租及旧结果被拒；它不证明旧 Agent 停止或外部动作不重复。

当前没有持久化的 Agent 启动确认、动作意图或 unknown 结果。会话 ID 在 Agent 结果提交时写入，而非进程启动时；已完成的 session 在后续 Ask/Later/retry 中可续用，尚未持久化的 session 则无法依 Hub 数据恢复。旧结果阻断和实际外部副作用是两个不同边界。

## Windows Runtime

[task.ps1](../../scripts/windows/task.ps1#L20) 为当前交互用户配置 At-Logon、Limited、IgnoreNew，启动 GUI bootstrap；[bootstrap.cs](../../scripts/windows/bootstrap.cs#L57) 隐藏子进程并将 PowerShell 放入 kill-on-close Job；[job.ps1](../../scripts/windows/job.ps1#L23) 将 launcher 放入另一 Job，握手后运行；[launcher.ts](../../src/platform/windows/launcher.ts#L166) 先启动 Hub 并等 ready，再启动 Worker，均 `windowsHide`。命名管道监听和 runtimeId/token 识别实例；组件异常退出时 launcher 调用 shutdown，而非自动重启组件。关闭 Job 对正常继承的受管后代提供进程生命周期清理；不能推广为所有外部独立进程均被清理，也不是安全沙箱。

本轮在临时 Home、随机端口运行 [tests/runtime-process.test.ts](../../tests/runtime-process.test.ts#L47)、[tests/windows-runtime.test.ts](../../tests/windows-runtime.test.ts#L94)、[tests/windows-bootstrap.test.ts](../../tests/windows-bootstrap.test.ts#L8) 和 [tests/windows-task-action.test.ts](../../tests/windows-task-action.test.ts)：11 项通过。前两项包括真实本地进程/Job 测试，非真实系统注销、重启或计划任务 at-logon 触发；其中 supervisor 测试使用既有 `dist`，本轮没有重建该目录，不能据此单独证明 dist 与 HEAD 一致。发布材料明确记录真实 reboot/logon 未测试；本轮也未操作正式计划任务或用户 Runtime。

## SQLite 与升级

[migration.ts](../../src/migration.ts#L42) 为 1–4 版本，每次启动在同一事务中应用缺失版本；中断时事务回滚的设计可从代码推断，强杀中断的完整升级测试本轮未做。关键唯一约束是 WorkItem 的 session、`(work_item_id,sequence)`、`(schedule_id,scheduled_for)` 和 notification delivery；没有通用 event delivery 去重或每项最多一个活动 Execution 的数据库约束。[tests/scheduling.test.ts](../../tests/scheduling.test.ts#L363)、[tests/realtime.test.ts](../../tests/realtime.test.ts#L314)、[tests/windows-runtime.test.ts](../../tests/windows-runtime.test.ts#L182) 构造旧结构检查升级；不等于所有历史用户库、崩溃时 WAL 或跨版本回滚已验证。本轮执行的核心 64 项包括 scheduling 迁移测试；realtime 和 windows-runtime 文件中相应覆盖分别为未执行及已执行。

## 本轮验证与限制

在默认受限环境运行五个测试文件时出现 5 项子进程失败，其中 scheduler 子进程明确 `EPERM`；可启动子进程的隔离复核结果为 **5 文件 64 项通过**。另运行 Windows 四文件 **11 项通过**，均使用隔离测试资源。没有运行完整测试套件、真实 Agent E2E、外部平台或真实系统注销/重启，且没有证明所有故障风险已复现。优先级为工程审计建议，实施前需用假 Agent 和临时数据库编写失败测试。
