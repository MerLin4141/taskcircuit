# TaskCircuit v0.2 — Test Strategy

> 测试草案不是测试结果。纯函数注入时钟、策略快照和可控 ID；SQLite 用独立临时文件和进程，所有外部服务为 fake，真实 Agent 必须另获授权。旧真实 E2E 只证明 `v0.1.2-real-agent-e2e-report.md` 中指定版本/场景。

## 确定性状态机

- Root created→active→waiting→active→completed；分别覆盖 failed/cancelled/expired/budget_exhausted、blocked 核实恢复及终态不可 reopen；deadline 与 cancel/commit 竞争。
- Work Item 每行按 [API 状态表](v0.2-api-proposal.md) 测 guard、授权者、持久影响；legacy 状态映射不暴露新 enum；新 WI 只属于一个 Root，subject 跨 Root 不共享 mutable 状态。
- Execution queued→running→结果；失权后旧 token 新提交拒绝，已 commit 相同 receipt 可只读确认；failed+unknown 不建 retry；输入/审批类型和版本/expiry 分别验证。
- Feedback union 全变体逐项验证 Root/WI/Execution、budget、互动变化；未知 schema/多字段冲突 fail closed。Pure decision 同输入、policy snapshot、time 和 ID→相同结果，不读时钟/随机/磁盘/网络。

## 真实 SQLite 与升级

- 从真正由旧版本生成的空库、完成、等待回答、Later、Retry、running/unknown、不同 Session/receipt/notification 的 v0.1.1 与 v0.1.2 库升级；旧 ID、外键、metadata、receipt、interaction、schedule 和 Session 全量比对；旧历史预算值 unknown。升级前备份、WAL、事务中强杀、重试幂等、磁盘不足/损坏恢复、FK/integrity check 与回滚后的可读性。
- 模拟旧 Hub/Worker 仍运行，验证外部维护窗口和进程排他措施阻止混写；v0.1.2 不会自行拒绝未来 schema，不能把这写成其内建保证。恢复旧备份前记录会丢失备份后的写入。旧 CLI/API 的 work、emit、schedule、answer、receipt 和 Windows Runtime 测试保留；不存在的顶层 `taskcircuit run` 不虚构。
- 两连接/两进程 `BEGIN IMMEDIATE` 并发创建同 source delivery：同摘要仅一事件和 Root，同键异摘要明确 conflict；同业务 subject 多次成功事件不错误去重，多 Root event links 正确。
- 每 Root 单一 active slot，与 budget reservation 及版本检查同事务；两个不同 WI 争用最后一次 Agent call，仅一个成功；重试算 attempt，重复 settlement 相同回执幂等、不同回执冲突。

## 故障注入

- Hub：事件前、持久 intake 后/decision 前、decision+reservation commit 后/派发前、firing 后/计划推进前，分别强杀并检查事务和 dedup。
- Worker：Agent 创建前明确失败可安全重试；Agent 开始后、产生伪副作用后崩溃/timeout、session ID 未持久化、lease expiry、晚到 result，保守 unknown + 冻结，不重复 Agent。
- Receipt：提交已 COMMIT 响应丢失、Hub 重启、同 identity/digest 与不一致 payload、临时 heartbeat/500 恢复、409 立刻 abort、安全期限止损；先 commit 后心跳 409 不覆盖已完成结果。
- Outbox（仅未来 fake）：决策 commit 后 send 前、外部已成功 response 丢失、远端幂等支持/不支持、过期 lease、重复矛盾 receipt；无法证明未发送则 unknown，不能重发。
- 定时/取消/人工审批：两个 scheduler 同 firing、时钟回拨、异常 firing 不阻塞其他 Root、答案重复/并发 conflict、审批摘要变化和过期、取消与 result 提交竞争；检查数据、调用次数与可观测原因。

## Agent、安全与平台

- 用 fake Agent 以确定性输出实现 `Continue → Continue → Complete`，恰好 3 次调用、3 个执行、共享 Root Budget、每次 Decision/timeline、有界后继；重复反馈和重复事件不会增加计数或派发。连续相同反馈、depth、deadline、次数、连续错误断路器分别触发，不能无限循环。
- 恶意 payload/feedback 包含 `cwd、profile、permission、budget、shell、rootId` 等覆盖建议，控制面必须拒绝/忽略且记录原因；不能因此声称同用户 CLI Agent 被 OS 隔离。Approval 仅经可信认证主体授权指定 digest；旧 Ask 答复不是批准。日志、receipt、timeline 禁止泄漏 token/credential/session ID。
- Windows fake process-tree、Job Object、Task Scheduler 隔离资源及清理；Linux 真机独立测试 Agent→child→grandchild、SIGTERM、SIGKILL、无关进程、失权和取消。跨平台结论仅覆盖实际运行环境；reboot/logon 若未执行明确 NOT TESTED。
- 真实 Agent 只在隔离 workspace、已明确授权、受控额度和无外部写场景下测试指定版本；mock 通过不能证明真实 provider 或 OS 安全。每个 Gate 记录 files、通过/失败/skip、环境和故障证据；失败不通过降低断言掩盖。
