# TaskCircuit v0.2.0 — Phase 2 Event Core

## Decision

用户选择：格式合法但未注册或无匹配路由的事件持久化为 `unroutable`，不创建 Root。旧 `/api/events` 对无匹配路由继续返回 not-found；`emit` 与 `work create` 保持原行为。

## Implementation

Generation 2 从 Schema 6 经 Migration 7 事务升级到 Schema 7，旧 Generation 1 不修改。保留原 `events`，为新事件添加版本、可信来源、时间、摘要和父事件信息；旧行不伪造来源或关联。`event_deliveries` 以可信 source instance 和 source-event ID 唯一去重；同身份同规范化摘要返回原 Event，摘要不同返回 409 并持久化摘要冲突审计。事件、Root、关联与去重在同一事务内提交。

事件可关联多个不同 Automation Root。相同 Automation 版本、可信 source instance 和 correlation key 复用非终态 Root；终态 Root 不重开，后续事件创建 successor。相关唯一性由部分唯一索引和单一 SQLite 写事务保证。可信内部子事件只能继承经过上下文校验的父 Root；外部正文不能指定可信身份或父 Root。

新 Event Core 不创建 Work Item、Execution，也不启动 Agent。`processed` 仅表示事件持久化及关联完成；未知类型持久化为 `unroutable`。原始 payload 在 SQLite 保存为规范化 JSON，单个 payload 最大 65,536 字节；非 loopback 的新事件写请求被拒绝。常见凭据字段及可识别凭据形态会被拒绝，不能视为完整秘密识别。Event show 会返回保存的 payload；本机控制面没有用户级认证或 OS 级隔离。

完整接口、去重身份及限制见 [API 说明](v0.2-api-proposal.md)；表、状态和迁移约束见 [Schema 说明](v0.2-schema-proposal.md)。

## 验证范围

隔离测试覆盖真实归档 v0.1.2 → Storage Cutover → Migration 6 → Migration 7，四个迁移强杀点、三个事件事务强杀点、同步双进程重复投递和关联、父事件权限、时钟偏差、未知事件、凭据字段、payload 大小、旧别名与 Root 事件分页。1,000 / 10,000 条事件及 1,000 次重复投递仅为 sanity 检查，不代表生产吞吐。

本阶段不运行真实 Codex / Claude，不操作正式用户数据库或 Runtime，不执行实际 Windows 重启/注销，不提交、推送、打标签或发布。

## 生命周期与可观测性边界

已关联事件在同一提交中记录 `received → validated → deduplicated → correlated → routed → processed`；这里的 processed 只表示 Event Core 处理完成。未匹配事件止于 `unroutable`，重复请求追加 `duplicate` 记录。无效请求不保存原始 payload，也不保证持久化拒绝记录；事务失败会回滚，不能保证存储故障仍能留下 failed 诊断。Event list 和 Root events 返回摘要；显式 Event show 返回保存的 payload，不能将凭据检测误认为完整脱敏。

本阶段没有公开 Automation 创建 CLI 或 REST API，事件的 Automation 选择需已有可信 Definition。多 Automation 目标是可信本机控制面输入，不从 payload 推导。重复事件在配置变化后仍返回原 Event 和原关联，不会自动补建 Root。
