## Channel contract

| Plugin kind | Supported API versions |
| ----------- | ---------------------- |
| Source      | 1, 2                   |
| Agent       | 1                      |
| Channel     | 1, 2                   |

The Registry loads each exact supported API version. API 1 Channel factories still receive a single `{ id }` argument. API 2 factories receive `{ id, config }` and a host with an abort signal and health reporting. They return the existing delivery interface and may provide a shutdown hook. The Hub starts cancellation before it waits for its dispatcher and bounds the optional shutdown hook to one second. API 2 health is held in memory and exposed via the management health response and Doctor.

`feishu-channel` is a built-in Channel API 2 implementation for outbound Feishu group custom bots. It requires two Hub-only environment references per instance and sends one text request per attempt. The fixed HTTPS Feishu v2 hook destination is validated before readiness, with redirects disabled. The request contains a seconds timestamp and the Base64 HMAC-SHA256 digest of an empty message, keyed by the timestamp, a newline and the signing secret. See the [operator guide](../feishu-channel.md) and [Feishu custom bot documentation](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot).

## Delivery behavior

- The Hub owns the same SQLite queue, 30-second lease, 5-second retry delay and 3-attempt cap. A late receipt cannot mark an expired or superseded claim as sent. The Channel issues one request per attempt.
- Success requires HTTP 2xx and numeric JSON `code: 0`. The 5-second default timeout can be configured from 1 to 10 seconds. A request also observes Hub shutdown. The Channel caps decoded response bytes at 64 KiB, message text at 12 KiB UTF-8 and the serialized request below 20,000 bytes.
- Provider failure leaves the Work Item and Root result intact and an open interaction answerable. Completion requires `notifyOnCompleted`. NeedsInput directs the operator to local Inbox and Answer. Later and retry waits produce no new notification.
- An accepted Feishu request whose success response is lost can produce a duplicate on retry. The delivery record protects local state, while the Feishu webhook has no TaskCircuit idempotency key.

## Security and compatibility evidence

- Two test instances used different validated targets and independent signing keys. The transport seam rewrote requests to loopback in tests only. Neither rules nor Channel config can select a module, executable, Agent, workspace, Root policy or Source.
- A rejected provider response deliberately echoed fixture credentials. Tests searched persisted records, including Events, Root, automation versions, notification deliveries and runtime changes, plus Doctor and captured error output. Credentials were absent. The dispatcher stored a generic failure.
- The shared Worker environment filter removes both configured names before external Agent import and on the Windows launcher's Worker spawn path. A standalone Worker test verified both variables were absent at import and in a child process, and neither names nor values were present in the Agent input.
- Local-console and the external API 1 Channel fixture continue to work. Local, Generic Webhook and GitHub Source behavior remains covered. Compatibility assertions now expect API 2 to load for Channel and reject unsupported Channel API 3 and Agent API 2.
- Package version `0.3.0`, database schema `10` and declarative schema `1` remain in place. No database migration.
