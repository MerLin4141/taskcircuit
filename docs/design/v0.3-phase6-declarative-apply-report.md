# v0.3 Phase 6 declarative apply report

Schema 10 stores the apply ownership marker in each immutable Automation Version snapshot. Existing policy reads the policy object and ignores the added management object; existing snapshots remain supported. SQLite version triggers and Root foreign keys preserve historical versions. The apply module validates all rules, compares canonical result digests, and performs creates and version changes under one `BEGIN IMMEDIATE` transaction without calling transaction-owning legacy helpers. Failures before commit roll back the batch. No Migration 11 is introduced.

Rules reference existing trusted Agent Profiles, Workspace Policies, exact local Source/type/Agent routes and Channel instances. Source identity is checked against trusted Event metadata at the existing policy decision boundary, not event payload. Notifications from the snapshot are carried into the Work Item metadata. A same-document identical reapply is unchanged; manual or cross-document ownership conflicts block the complete batch. Missing rules are left alone. The file itself is not part of the SQLite transaction.

`tests/declarative-apply.test.ts` covers creation, reapply, versioning, pinned Roots, ownership conflicts, invalid plans, rollback, local Source identity, trusted prerequisites and CLI output. The implementation does not add active external Source routing, authentication, a sandbox, implicit startup apply or prune. Real Codex and Claude were not run during this phase.

The target checkout completed format check, typecheck, build, and the full test suite: 53 files, 474 tests passed, 0 failed, 0 skipped. `npm audit` reported 0 vulnerabilities. The suite includes pre-existing uncommitted Phase 5 tests preserved in the checkout. Real Codex and Claude E2E were not run.
