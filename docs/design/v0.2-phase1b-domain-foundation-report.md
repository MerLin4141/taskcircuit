# TaskCircuit v0.2 Phase 1B — Domain Foundation

This phase builds on the Phase 1A storage generation cutover: Generation 1 remains quarantined at schema 4; Generation 2 moves from schema 5 to 6. Migration 5 is the storage cutover and Migration 6 is the domain migration. See [Migration 6](v0.2-migration6-report.md) for mapping, tests and limitations.

The domain has stable Definitions with immutable versions, Roots pinned to one version, and non-null Work Item ownership. Manual event creation atomically creates an implicit Root. `taskcircuit work create <event-type>` is an alias for `emit <event-type>`, as selected by the user. A Root can own multiple Work Items; claims serialize active Agent execution per Root. Sessions belong to a single Work Item; an already blocked Root does not automatically restart due to an answer, schedule or child state change. Root-wide cancellation, Policy, Event ingestion changes, Budget, Outbox and plugins are not implemented.

Validation uses temporary SQLite databases and fake Agents, including the archived real v0.1.2 code, five process interruption points, concurrent migration and a 1,000-item sanity test. Phase 1A tests and the existing full test suite are retained. The Hub regression tests use isolated Generation 2 databases. The old test that deliberately removes schema 2 from a database runs against the archived v0.1.2 Hub; it is not a supported Generation 2 downgrade. The v0.1.1 fixture tests use a synthetic Generation 2 marker for isolated domain regression; the separate v0.1.2 full-path test exercises the actual quarantine and cutover. Real Agents and the formal user runtime/database were not used.

## Validation and limits

- Storage generation: Phase 1A tests retained, including old-runtime writer barrier, quarantine, crash recovery and concurrent cutover.
- Migration 6: real archived v0.1.2 → cutover → schema 6; five real process-termination points; two synchronized migration processes; 100 and 1,000 historical Work Items.
- Definition and Root: immutable versions, pinned Root version, terminal-state and predecessor checks, same-subject uniqueness, multiple Work Items and single active claim per Root.
- Compatibility: the isolated Generation 2 tests cover Ask/Answer/Resume, Later, Retry, P0, P1, scheduling, fake CLI and Windows runtime unit tests. Historical receipt, interaction and session records are compared across migration.
- User-selected CLI compatibility: `work create <event-type>` aliases `emit <event-type>`.
- Future schema: version 7 rejected with `database_schema_too_new`. Schema 6 is accepted on restart.
- No Root-wide cancellation, external Agent invocation, actual Windows reboot/logon, formal runtime, budget enforcement or new integration was performed. Process termination cannot retract external side effects.
