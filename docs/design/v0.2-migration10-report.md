# TaskCircuit Migration 10 — Loop Limits

Migration 10 upgrades Generation 2 schema 9 to schema 10 in one SQLite transaction. It adds `automation_roots.max_runs` and `deadline_at`, derives fixed values for existing automation Roots from their pinned immutable Definition snapshots and trusted `created_at`, adds immutability / required-value guards, and creates a unique partial index on a Continue successor's parent Execution. Manual and legacy Roots retain NULL limits and existing behavior. Missing loop configuration takes the newly defined finite defaults (8 runs and 7200 seconds), applied as an explicit migration policy. No external data or historical feedback is fabricated.

Generation 1 is not a Migration 10 target. On a failure or interruption before COMMIT SQLite rolls back the schema and data changes together; the migration can be rerun. Schema 11 is rejected. Rollback after a successful upgrade requires an appropriate backup and would lose writes made since that backup; old binaries must not write to a new-generation database. Test claims and limitations are detailed in [Phase 5](v0.2-phase5-loop-limits-report.md).
