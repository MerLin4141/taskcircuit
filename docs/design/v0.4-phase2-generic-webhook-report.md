# TaskCircuit v0.4 Phase 2 Generic Webhook report

Phase 2 builds on Phase 1 commit `37abb382e9854a09258d8debc082e6bf9d4f392c`. Package version remains 0.3.0, database schema 10, and declarative schema 1. Source API 1 and API 2, Agent API 1, and Channel API 1 remain supported.

The Hub owns the [loopback integration listener](../../src/integrations/ingress.ts) and reserves one exact path per configured HTTP Source. The [Webhook implementation](../../src/plugins/builtin/webhook.ts) registers its handler through the Source API 2 capability. It receives bounded raw bytes and normalized headers without access to the management router or SQLite. Management endpoints are absent from the ingress listener. The ingress binds before the Source startup gate opens. A bind or required Source startup failure blocks readiness and releases the listener.

The listener admits up to 32 in-flight requests by default, with a two-second body-read bound and seven-second request budget. It limits the raw stream to 131,072 bytes. Before JSON parsing the Source validates HMAC-SHA256 against the raw body in constant time. The stable delivery header defaults to `X-TaskCircuit-Delivery`. Event Core retains its 65,536-byte canonical payload bound, transaction, and durable receipt identity. The Hub performs only durable intake on the request path and temporarily limits SQLite busy waits to 250 ms there. SQLite write contention returns 503 without acknowledgment or partial persistence.

The Hub continues to bind source instance and `external_untrusted`. Apply accepts a rule for a configured Source instance only when its name, type and Agent match trusted routing and workspace policy. A route waiting for its applied definition returns 503 before persisting; an intentional unroutable delivery returns 202 after commit. Original Root links preserve routing authority for duplicate and conflicting redeliveries after restart or a configuration change. No migration is needed.

During shutdown, ingress closes admission, drains admitted requests for up to 200 ms and aborts remaining request signals. Source cleanup has a 1.2-second asynchronous stop bound before sockets and SQLite close. The listener and Source diagnostics expose fixed statuses, excluding raw bodies, HMACs and secrets.

The Hub resolves configured secret environment references once. The [Worker environment filter](../../src/integrations/environment.ts) removes those references at Windows Launcher fork and, for standalone Workers, before external plugin import. The built-in Agent process filter remains in place. The regression runs a real Worker with a fixture Agent to check its import environment, execution input and child environment. Trusted Local plugins remain in-process code with the operating user's authority. The filter is a runtime environment boundary, without an OS isolation guarantee.

The [loopback regression](../../tests/webhook-e2e.test.ts) covers raw signature bytes, invalid input, both body limits, Management API isolation, distinct instance keys, startup and shutdown, concurrency, SQLite contention, and durable replay after lost response, restart, route change and disablement. The [operator guide](../webhook-source.md) includes configuration, PowerShell signing, retry semantics and the HTTPS proxy topology.

GitHub Source, Feishu Channel and external provider verification belong to later phases. Phase 2 work remains uncommitted for review.

Validation passed on Windows with Node 24. The complete suite ran 507 tests in 55 files, with zero failures or skips. Typecheck, build and the dependency audit passed with zero vulnerabilities. The direct format check flagged 31 unchanged CRLF baseline files. The full format check passed with all Phase 2 edits overlaid on the LF checkout used by Windows CI.

A separate real loopback smoke run used isolated Hub and Worker processes, temporary state, a generated test secret and the built-in Mock Agent. Apply created the source-scoped rule. HTTP returned 202, 200 and 409 for acceptance, exact redelivery and changed content. SQLite contained one delivery, one Root and three completed-loop executions. Doctor reported healthy and the secret was absent from Doctor output, captured component logs and queried persistence rows.
