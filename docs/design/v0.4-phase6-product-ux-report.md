# TaskCircuit v0.4 Phase 6 — Product UX

Phase 5 was committed as `dd4a9684928d58ac85604fb383ed4fe28948888f` (`docs: add automation templates`) and pushed to `origin/v0.4-dev`. Phase 6 is a local worktree change.

## Configuration selection

Hub, Worker, Doctor, and Windows runtime install/run use the shared selector. The precedence is `--config <path>`, then `TASKCIRCUIT_CONFIG`, then the invoking directory's `taskcircuit.config.json`, then built-in defaults. The selector resolves relative paths before loading and reports explicit missing selections. The selected file's directory anchors relative external plugin references.

A new Windows task carries the selected absolute path or the explicit built-in-default selection. PowerShell Job startup passes the selection to Launcher, Hub and Worker, and Worker environment filtering uses the pinned configuration. Older tasks without a pin retain the application-directory fallback when no environment selection exists. Runtime status exposes the config path, and managed startup logs use fixed error codes and operator hints. Secrets remain in the operator-managed environment. Reinstall to pin a project config on an older task.

## Doctor and first use

The preflight checks config syntax and bindings, project workspaces, configured Agent CLIs, integration listener settings, Source and Channel configuration, and required environment references. Environment output contains names and SET/MISSING states. Optional Source issues and an offline Hub are warnings. Fatal config issues exit 1. External plugin code loads at runtime startup. When Hub is reachable, Doctor adds schema, Worker state, integration listener, and Source/Channel health. It uses local diagnostics and never sends a provider message or webhook.

The [v0.4 Quick Start](../quickstart-v0.4.md) leads with a local Mock run, then GitHub Issue Fixer and the provider-neutral Webhook Task Runner. It shows foreground and managed setup, preflight, apply, local answer and notification. Both repository READMEs link to it. The CLI groups common commands and gives an actionable start instruction when apply cannot reach Hub.
