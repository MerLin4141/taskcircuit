# TaskCircuit v0.2 — 当前架构地图

> 审计基线：v0.1.2，main / `2652ca100bb37abf79b75618cc6991e00721e897`。本文件是静态源码审计；既有真实与假 Agent 证据见 `v0.1.2-real-agent-e2e-report.md`。设计目标不是当前事实。

```text
CLI / loopback HTTP → Hub (routes, scheduler, notifications)
                         ↕ SQLite (业务表、租约、回执)
                       Worker → Adapter → Codex / Claude / Mock
```

入口和事务在 `src/hub.ts:57-82,880-953`；Agent Worker 在 `src/worker.ts:42-354`；schema/migration 1–4 为 `src/migration.ts`（没有 `src/db/`）；协议与配置为 `src/agents/protocol.ts`、`src/adapter.ts`、`src/config.ts`。当前 Hub 的 `createEvent` 匹配 `(source,type)` 后在一个事务创建新的 Event、Work Item 和首个 queued Execution；没有 delivery ID 去重、Root 或策略决策表。未匹配路由时不创建成功工作。Worker 使用执行租约和 heartbeat；claim 在 `BEGIN IMMEDIATE` 中将 queued 直接转 running，旧结果通过 worker+token+expiry 校验。正常结果和可选 receipt 同事务写入；结果提交冲突不延长租约。

## 当前实体（不是目标模型）

| Entity / 主键                                     | 用途、生命周期及所有权                                                                                                    | 关系、持久化与 API / 关键不变量                                                                                                                                                                                                                   |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Event `events.id`                                 | 已匹配的输入事件；当前没有显式 lifecycle 或来源真实性证明。Hub 写入。                                                     | SQLite `source,type,payload,created_at`；Work Item metadata 的 `eventId` 指向它，未建 FK。`POST /api/events`；重复相同请求仍可创建新事件。                                                                                                        |
| Work Item `work_items.id`                         | 一个持久任务；Hub 管理 active、waiting_input、waiting_schedule、completed、failed、cancelled。                            | FK agent_profile；多 Execution、Interaction、Schedule；metadata 含 eventId 和 receipt ledger。`GET /api/work-items[/:id]`、`POST /:id/cancel`。没有 Root FK。                                                                                     |
| Execution `executions.id`                         | 一次运行；queued → running → completed/failed/waiting_input；Later 和安全 Retry 再派生新的执行。Hub/Worker 通过租约协作。 | FK Work Item/Agent Profile/Session；`UNIQUE(work_item_id,sequence)`；claim、heartbeat、result API；过期运行结果为 failed + `execution_outcome_unknown`，不能自动重做。`claimed/retry_wait` 是类型中存在的名字，不能仅凭类型声称实际所有路径使用。 |
| Agent Session `agent_sessions.id`                 | 已建立的外部会话；Hub 保存、Worker 后续复用。                                                                             | `work_item_id UNIQUE`；零或一 Session/Work Item，多个 Execution 可引用；详情经 Work Item API 返回，CLI 有脱敏。没有 Root 边界。                                                                                                                   |
| Interaction `interactions.id`                     | 需要输入的问答；open → resolved/cancelled。                                                                               | FK Work Item/Execution；`POST /api/interactions/:id/answer` 原子解析回答、创建后续 Execution；`GET /api/inbox`。当前 Ask 不是具备主体认证和动作绑定的 Approval。                                                                                  |
| Schedule `schedules.id`                           | once/cron 或 work-owned Later/Retry；active/paused/cancelled/completed。Hub scheduler 管理。                              | 可关联 parent Execution 和 work owner；`schedule_firings` 对 `(schedule_id,scheduled_for)` 唯一；公开 `/api/schedules` 与 pause/resume/delete。tick 固定墙上时间，每项单事务；重复记录仅本 tick 隔离。                                            |
| Runtime Change `runtime_changes.sequence`         | 数据库触发器记录部分状态变化，SSE 消费，可裁剪。                                                                          | `GET /api/stream`、`/api/stream/head`、`/api/state`；不是完整事实日志，不能声称可重建全部状态。                                                                                                                                                   |
| Notification `notifications.id`                   | Work Item/Interaction 的通知，open/resolved 等状态由 Hub 维护。                                                           | FK Work Item/Interaction，`dedupe_key UNIQUE`；`GET /api/notifications`。通知失败不等于业务完成。                                                                                                                                                 |
| NotificationDelivery `notification_deliveries.id` | 按 Channel 异步投递，有状态、attempt、not_before 与租约。                                                                 | FK Notification，`UNIQUE(notification_id,channel_id)`；队列由 dispatcher 领取，通知 API 可观察投递；当前内置 local-console。                                                                                                                      |
| Agent Profile `agent_profiles.id`                 | 匹配事件时由配置 upsert 的代理信息，Work Item/Execution 引用。                                                            | SQLite JSON config；可信配置来自 `src/config.ts` / 配置文件。现有 profile 不是每个 Root 的不可变策略快照。                                                                                                                                        |

补充：提交回执不是独立 schema 表，位于 `work_items.metadata.taskcircuitResultReceiptsV1[executionId]`，查询 `GET /api/executions/:id/result-submissions/:submissionId?digest=...`；旧请求无 identity 仍按旧行为。`src/result-receipt.ts` 为 wire JSON 规范化 SHA-256。实际外部动作没有 exactly-once 保证。

## 当前安全与差距

`src/agents/protocol.ts` 将 Event payload 作为 context 放进提示词；Trusted Local 同用户进程没有 OS 文件/网络隔离，也没有一般性入站来源身份认证或多用户授权。外部内容可影响模型建议；目前不可声称它不能影响 Agent 的实际工具动作。v0.2 需要可信策略快照、受控执行和新的持久约束才能兑现控制面目标；数据模型本身不是安全沙箱。实时 feed 可裁剪，不能替代 Root Timeline 事实账本。
