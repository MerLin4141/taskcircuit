The candidate follows Phase 6 commit `07dff0b909cccc6842ef47c8ea8e2c26f6907d01`. Package version is 0.4.0, Database Schema is 10, and Declarative Schema is 1. The compatible plugin versions are Source 1/2, Agent 1, and Channel 1/2. The test suite rejects Agent API 2 and Channel API 3.

## Local verification

- The real v0.3.0 release binary generated an isolated Schema-10 database with an open question and an applied Schema-1 Automation. The v0.4 binary opened it and finished the same Root and session. Dry-run performed no writes, unchanged reapply retained the version, and the old and new Roots pinned versions 1 and 2 respectively.
- The full Windows regression covers lease fencing, uncertain execution, result receipt, continuation, cancellation, retry and recovery, Generic Webhook, GitHub Source, simulated Feishu, both templates and the Product UX. The Phase 6 Windows CI log showed the Doctor subprocess in the Feishu test exceeded its original four-second test budget. The candidate gives that subprocess and enclosing test bounded time for PowerShell startup while retaining their assertions.
- With active Webhook and GitHub Sources configured locally, signed Webhook deliveries survived Hub restart and replayed as 200 with exactly two original Roots. After Worker restart, the pending Ask and Later each completed in two executions using their original sessions. Completion recorded two local notification deliveries.
- Two real Windows temporary scheduled tasks, one with an external spaced Unicode config and one with built-in defaults, passed install/start/status/Doctor/restart/stop/uninstall. The external relative Worker plugin completed work. Metadata and both tasks were cleaned. The isolated application copy set a test-only port in its Job script to avoid the existing default-port runtime.
- Synthetic secrets were absent from Doctor text and JSON, component logs, tested SQLite records, scheduled task arguments and runtime status. Worker plugin import and Agent child checks verified exclusion. Listener and signed-request tests exercise loopback separation, required signatures, fixed Feishu destination and redirect rejection.
- Local format checks use an LF overlay for the pre-existing Windows checkout differences. The required Windows and Ubuntu jobs are verified against the candidate SHA on GitHub Actions.
