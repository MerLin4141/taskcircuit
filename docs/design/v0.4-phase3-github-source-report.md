# TaskCircuit v0.4 Phase 3 GitHub Source report

Phase 3 builds on Phase 2 commit `f646cb958f845556657e10348430fcdf99f398a7`. Package version is 0.3.0, database schema is 10, and declarative schema is 1. Source API 1 and 2, Agent API 1, Channel API 1 and Generic Webhook remain supported.

The [GitHub Source](../../src/plugins/builtin/github.ts) registers as `github` through Source API 2. Each configured instance receives an exact POST path on the existing loopback ingress. The [shared webhook helpers](../../src/integrations/http-webhook.ts) verify HMAC-SHA256 over the raw bytes before decoding JSON and map durable intake receipts to HTTP responses. The built-in Generic Webhook retains its TaskCircuit headers and configurable event mapping.

The GitHub Source accepts `issues.opened` and `issue_comment.created` on Issues. Authenticated ping, PR comments and unselected event/action pairs return bodyless `204` without a durable Event. Two mandatory per-instance numeric allowlists restrict repositories and senders. The bounded projection discards unselected GitHub fields and headers. The Source submits the fixed type, unchanged GitHub delivery ID, and repository/Issue correlation key. The Hub binds the instance identity, `external_untrusted` context and trusted route. Persisted delivery authority handles duplicate and conflicting redeliveries across restart and route changes without a migration.

The Source resolves the referenced secret in the Hub through the shared [integration environment](../../src/integrations/environment.ts). Windows Launcher and standalone Worker filter those references before external Agent code loads. The existing Agent environment filter also removes TaskCircuit variables from the Agent child. The projection rejects the configured secret if it appears in a field that would be persisted. HTTP errors and Source health contain fixed diagnostics. The signature, headers and raw provider payload are never persisted or logged.

The [GitHub Source tests](../../tests/github-source.test.ts) use four synthetic GitHub payloads and the public signature test vector. The operator setup, payload bounds and inbound trust boundary are documented in the [GitHub Source guide](../github-source.md). Public GitHub delivery and real Codex validation remain RC work. This phase introduces no polling, PAT, GitHub API client, write-back or PR creation.

Windows validation passed with 526 tests in 56 files, including 19 GitHub Source tests and all 14 Generic Webhook tests. Typecheck, build and Git whitespace checks passed. The dependency audit found zero vulnerabilities. The working checkout reported 31 unchanged CRLF baseline files. The complete format check passed on the LF copy with all Phase 3 changes.

A separate loopback smoke test started an isolated Hub and Worker. Apply installed the GitHub Issue rule, a signed Issue received 202, exact redelivery received 200, changed projected content received 409 and a signed PR comment received 204. SQLite contained one delivery and one Root. The Mock Agent completed after two executions and one local Inbox answer. Doctor reported healthy. The generated secret was absent from captured component logs, queried storage, Doctor output, Worker plugin import and its spawned child environment.
