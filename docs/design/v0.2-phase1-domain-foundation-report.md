# TaskCircuit v0.2.0 Phase 1 — Domain Foundation 报告

**历史状态：最初 Phase 1 曾因旧版写入排他问题阻塞；后续见 Phase 1A / 1B 记录。**

## Migration safety

- 真实 `v0.1.2` tag 代码归档与临时数据库实验：旧版的未来 schema 拒绝 **NOT PRESENT**。模拟 version 5 后，旧 Hub 启动、旧 CLI 读取、旧 Mock Worker 领取以及旧 Scheduler 触发均成功。
- 独立旧 Hub 活动时，未启动 Launcher 的临时 Home 的 Runtime 状态仍为 stopped；其他端口空闲不代表没有 Hub。另一个旧 Hub 能同时打开同一临时数据库并写入。参见 [安全实验与后续方案](v0.2-migration-safety-report.md)。
- Upgrade exclusivity：**UNSOLVED**。迁移测试未接触 `%USERPROFILE%/.taskcircuit` 或正式 Runtime；未自动停止或终止任何用户进程。

## 实施范围

- Migration 5、fresh v5、真实 v4→v5、rollback、重开、future-schema guard：**NOT IMPLEMENTED / NOT RUN**；仅 version 标记探测不是迁移。见 [Migration 5 报告](v0.2-migration5-report.md)。
- Automation Definition / immutable version、Root / transition / predecessor、Work Item Root ownership：**NOT IMPLEMENTED / NOT TESTED**。
- 新版 manual compatibility、Later、Retry、Session、P0/P1/Scheduler/Fake CLI/Windows 回归：新 Domain 下 **NOT TESTED**；v0.1.2 已有回归不等于新版本实现通过。

- 为遵守 LOCAL_ONLY 文档不得修改的要求，未对整个工作区运行会写入文件的 `npm run format`；仅对本轮新报告执行 Prettier，随后运行全仓 `format:check`。
- Real Agent：**NOT RUN**；Formal user DB：**NOT TOUCHED**；Git commit / push / tag：**NO**。

下一步先决定并验证能够阻止旧访问者在检查后重新打开数据库的外部维护/访问控制边界，形成可执行的独占方案；在此之前不要启动自动 Migration 5。备份责任及回滚限制详见安全报告与 schema proposal。
