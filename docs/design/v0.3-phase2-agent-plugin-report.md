# v0.3 Phase 2 Agent Plugin report

## Before and after

Previously `workOnce` imported and constructed Mock, Codex and Claude adapters directly, with Mock-specific working-directory and demo-sequence handling. It now gets the Agent Plugin by the existing `agentProfile.adapter` ID from an explicitly composed Worker registry. `src/plugins/builtin/agents.ts` registers three thin wrappers through the same Registry. The wrappers reuse existing adapters and retain their input and workspace behavior. No external loader, config generalization, Source or Channel dispatch is introduced.

## Execution and compatibility

The Agent Plugin extends the existing `AgentAdapter` contract: instruction, event data, previous answers, workspace, external session ID, model and AbortSignal flow through the existing paths. Agent feedback still uses `AgentResult`; adapter invocation, CLI arguments, protocol parsing and error classification remain unchanged. Worker lease fencing, result reconciliation, session persistence, cancellation and scheduler behavior were not intentionally changed. `workOnce` retains its existing optional test adapter argument; production CLI uses the registry.

## Verification and limitations

`tests/agent-plugin-integration.test.ts` exercises builtin manifests, Worker dispatch to Mock and an injected test-only Agent with session ID and signal. The existing full regression suite covers Mock session, feedback, scheduling, P0/P1 and cancellation behavior. Real Codex and Claude E2E were not run in this phase; no real compatibility claim is based on fake tests.

Remaining Agent-specific coupling: trusted config validation/defaults and CLI Doctor's Codex/Claude capability checks; Agent implementations and builtin registration necessarily name their implementations. The Worker claim type still reflects the v0.2 config union. Schema remains 10; package version remains 0.2.0.
